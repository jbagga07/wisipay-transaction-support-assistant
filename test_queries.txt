Q17.
What is the difference between error codes F500, F502, and F503 according to the error dictionary? Which specific transactions in the dataset experienced each of these codes as an intermediate state before ultimately succeeding?
Answer:
----------------------------------------
The differences between the error codes are as follows:

*   **F500**: An internal server error occurred at the provider while processing the request.
*   **F502**: The provider gateway received an invalid response from an upstream bank or clearing system, typically indicating a network or connectivity issue.
*   **F503**: The provider service is temporarily unavailable, usually due to overload or maintenance.

The specific transactions that experienced these codes as an intermediate state before ultimately succeeding are:

*   **F500**: TXN10030
*   **F502**: TXN10042
*   **F503**: TXN10052

Q18.
According to the error code dictionary, what must the system do when it encounters a TIMEOUT status? Why is it dangerous to immediately mark a TIMEOUT transaction as FAILED, and which transactions in the dataset illustrate this risk?
Answer:
----------------------------------------
When a TIMEOUT status is encountered, the system must not mark the transaction as FAILED immediately. Instead, it must query the provider's status API using the PROVIDER_REF. If the provider confirms there is no record, the transaction can be marked as FAILED and a retry allowed; otherwise, it should be marked as SUCCESS or REVERSED.

It is dangerous to mark a TIMEOUT transaction as FAILED immediately because the transaction state is UNKNOWN—the payment may or may not have been processed by the provider.

The following transactions in the dataset illustrate this risk:
- TXN10022 (Arjun Sharma to Meera Patel, 870.00 INR)
- TXN10039 (Vikram Nair to Arjun Sharma, 1750.00 INR)
- TXN10058 (Vikram Nair to Ananya Iyer, 3100.00 INR)
